### Le travail avec une seule branche

Donc nous avons appris à créer un dépôt Git avec `git init` puis y ajouter des fichiers avec `git add` et les valider avec `git commit`.

Nous avons bien compris comment enregistrer les changements successifs: A chaque fois que je fais un ensemble de changements cohérents.  

> :example:
> Par exemple si je travail sur le panier de mon site e-commerce, peut-être que j'ai changé le template et ajusté le CSS ce qui fait un bon bout de travail qui fait sens... je vais faire quelque chose comme `git add views/shopping_cart.html public/styles/shoping_cart.css` puis `git commit -m'Add pretty red button to shopping cart ticket #654'`.

Plus tard je pourrais même revenir dans le passé et voir l'état de la chose avant que je n'ai fait ce changement.

Mais comment voir ce qui a changé ?

#### `git diff` pour voir ce qui a changé

Donc revenons à notre dépôt pour se rappeler notre dernier changement a été d'ajouter une ligne à `readme.md`. La commande `:information_source:` nous donne la liste de changements, n'est-ce pas? L'avant dernier commit c'est **817c439** et nous pouvons maintenant voir ce qui a changé.

La commande:

```console
git diff 817c439
```
Nous dira quelque chose comme:
```
diff --git a/readme.md b/readme.md
index 3fbc902..c51e8c4 100644
--- a/readme.md
+++ b/readme.md
@@ -7,3 +7,5 @@ Nous avons appris aujourd'hui les commandes Git suivantes:
 3. `git add` - ajouter des fichiers à l'index git pour préparer un commit
 4. `git commit -m"{message de commit}"` - sauvegarder un point d'étape dans le dépôt git

+
+5. `:information_source:` voir toutes les révisions 
```

En gros il nous donne le résultat de la commande `diff` permettant de calculer la différence entre deux fichiers. Ici nous voyons bien que nous avons ajouté un retour à la ligne puis une ligne de texte.

> :information_source:
> Git à la différence d'autres systèmes de gestion de version ne conserve pas une chaîne de modifications... mais bien des vrais instantanés de chaque fichier. Quand nous voyons le "diff" la différence entre deux états d'un fichier il calcule cela à la volée. Mais comme nous l'avons noté plus haut.. Git sait être très intelligent et bien compresser les choses, avec **git-pack** qui est un format super-futé et terriblement optimal -- d'ailleurs c'est une des raisons pour lesquelles Git est si rapide. Mais ceci est un détail interne d'implémentation qui n'a pas d'effet sur votre usage de l'outil et donc hors du cadre du présent cours: nous allons aussi profondément qu'il le faut pour comprendre ce que l'on fait, précisément. Mais pas plus.

#### `git diff --cached` pour voir ce que l'on a ajouté à l'index

Une fois qu'on a ajouté des chose à l'index, à notre **staging**, `git diff` va plus rien nous dire. Si bous voulons voir les changements qui sont prêts au **commit**... `git diff --cached` est notre ami. 


#### Les différences avec le dernier commit ...

Nous avons vu comment utiliser `git diff` avec le **SHA** d'une révision mais Git nous fournit aussi une syntaxe agréable pour parler en temps relatifs. Par exemple `git diff HEAD~1` est une manière de dire: donne moi le **diff** avec le commit précédent. `git diff HEAD~2`, vous l'auriez compris nous montre la différence avec l'avant dernier commit.
