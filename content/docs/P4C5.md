# Shining in society and amazing friends with Gitfoo.

# Tip 1

I made several modifications in a file and I don't want any
commit only part:

    git add -p

For each file modified in your working tree, it offers you to
add each hunk back to the staging area.

More informations ?

    git help add

# Tip 2

I want to know who committed to a project.

    git shortlog -n -s

Will return the list of authors sorted by their number of commits.

    git help shortlog

# Tip 3

I want to delete remote branches that no longer exist.

    git fetch -p origin

Will retrieve objects from origin and remove remote branches that
no longer exist. You will have a correct 'git branch -a'.

# Tip 4

I want to revert to a commit forgetting whatever is in progress:

    git reset --hard SHA1

Will put you in the state of the commit as a parameter. Anything you may have modified or committed is (well, not quite) lost.
If you have already pushed the commits in question this is bad practice.

    git help reset

# Tip 5

I want to initialize a git repository for my system config.

    git init /etc

Will initialize a git repository in /etc. So for your piece of code
which-will-not-be-reused-it-is-on, git init && git add . && git commit.

    git help init

# Tip 6

I want to know which branches a commit is on.

    git branch --contains SHA1

You will list the branches in question.

    git help branch

# Tip 7

I want to undo my last commit.

    git reset --soft HEAD^

Your last commit will be undone and your changes will be put in
your staging area. FYI this is what git commit --amend does.

    git help reset

# Tip 8

I want to add a cool 'chuck' command that responds 'norris' (ahah).

    $ cat > /usr/local/bin/git-chuck <<< EOF
    #!/bin/sh
    echo 'norris'
    EOF
    $ chmod +x /usr/local/bin/git-chuck
    $ git chuck

This will create a "git-chuck" executable that simply responds "norris".
git recognizes executables named git-xxx.
This is how it works:

* git-pulls: https://github.com/schacon/git-pulls
* git-pair: https://github.com/chrisk/git-pair

and many others.

# Tip 9

I want to see commits that are in one branch and not in another.

    git log origin/master --not origin/develop

You will list the commits that are in the master branch but not in develop.

    git help log

# Tip 10

I want to retrieve a commit that is on another branch.

    git cherry-pick SHA1

Will retrieve the SHA1 commit and apply it to the current branch. Be careful, the parent commit is not the same, the SHA1 will change.

    git help cherry-pick

# Tip 11

I want to check that my modifications do not add spaces at the end of
line or space before a tab.

    git diff --check

Displays each detected error and an error return code.

More informations ?

    git help diff

# Tip 12

I want to make an archive of my git repository.

    git archive --format tar -o backup.tar HEAD

You will create a backup.tar tarball of the HEAD.

    git help archive

# Tip 13

I want to see commit messages with the diff.

    git log -p

Will show you a classic log view but with the diff just below.

    git help log

# Tip 14

I want to visualize the changes in a readable way for text.

    git diff --color-words

Will display the differences for each word rather than by line.

    git help diff

# Tip 15

I want to search for "plop" in my git repository.

    git grep "plop"

Will return all rows that have "plop".

    git help grep

# Tip 16

I want to search for a modification that adds or removes "plop"

    git log -S "plop"

Will return all revisions where "plop" is found. To be used with the -p option in general.

    git help log

# Tip 17

I want to prepare my patches to send them by email.

    git format-patch SHA1

Will write the patch to a file, to send it by email for example, or simply to share it.

    git help format-patch

# Tip 18

I want to check out a file for the next commit.

    git rm --cached path/to/file

Will mark the file for deletion for the next commit but will not remove it from the filesystem. Convenient if you've done something stupid :).

    git help rm

# Tip 19

You want to find the commit that introduced a regression.

    git bisect start

Will start a bug finding session. Bisect will place you on
specific commits, and you'll need to mark them good or bad to
finally find the corresponding commit.

    git help bisect

# Tip 20

I want to optimize a somewhat large git repository.

    git gc

Will delete all lost objects and compress number of revisions. If your repository is a bit big, git launches gc automatically.

    git help gc

# Tip 21

I want to see what I will commit:

    git diff --cached

Returns you only the differences of your staging zone.
Great combo with yesterday's order:

    git diff --cached --check

Will return trailing whitespace errors for your area
staging.

More informations ?

    git help diff

# Tip 23

I want aliases for my usual commands.
In ~/.gitconfig, I add:

    [a.k.a]
      st = status
      a = add
      ci = commit
      br = branch
      co=checkout
      cpk=cherry-pick
      d = diff

These aliases will be immediately available,
without having to recharge anything.

# Tip 24

I want colors everywhere!
In ~/.gitconfig, I add:

    [color]
      ui=true
    [color "diff"]
      meta=yellow
      frag = cyan
      old = red
      new = green

In diffs, deleted lines will be
in red and those added in green.

# Tip 25

When I write my commit message, I want to use my 
 favorite text editor, for example vim. In ~/.gitconfig, I add:

    [core]
      editor = vim

With commit messages, feel free to spread over more than a single line if your patch is not trivial, while  eeping the first line less than 50 characters.

# Tip 26

      for dates at the social network ("n hours ago")

      to display the names of modified files
    --no-merges

# Tip 27

It is possible to format the logs at will:

    git log --pretty=format:'%Cred%h%Creset %s %Cgreen(%cr) %Cblue<%an>'

With :

    %C to change the color
    %h for abbreviated SHA1
    %s for commit subject
    %cr for relative date
    %an for author name

More information about pretty format:

    man git show

# Tip 28

I want to display only one person's commits:

    git log --author="John Smith"

I can also make an alias to show only my commits:

    mylog=!git log --author=`git config --get user.email`

The exclamation mark requests direct execution by bash.

# Tip 30

I want to create a git repository from another repository to keep some history.

For example to create a git repository from the lib/captcha subdirectory.

    git filter-branch --subdirectory-filter lib/captcha -- --all

filter-branch will replace your current git repository keeping only files and commits matching lib/captcha.
lib/captcha will therefore become the current directory.

You can also delete a file from your git history.

    git filter-branch --index-filter 'git rm --cached --ignore-unmatch config/prod.yml' HEAD

Will rewrite all commits so that the config/prod.yml file is no longer there.

    git help filter-branch

To test these commands, use a new clone of your favorite project. Or wait for the latest Git "Hardcore" Daily.

# Tip 31

You want to rewrite your git history to group commits, remove some, and generally change everything.

    git rebase -i SHA1

SHA1 being the starting commit, which you don't want to modify. All those at
above can be rewritten. Git opens your *EDITOR* and asks you what
operations you want to do. You can keep the commit as it is, the
merge with the previous one, delete it.

    pick 379ab2a Move all presence as pid.
    pick 42bab02 Update timeout module to use the new presence api.
    pick d1da4b4 No more indexes for uce_presence_mongodb.
    pick 94835c2 No more indexes for uce_presence_mnesia.
    pick 0a481e9 Optimize uce_paginate.
    pick 09b4224 Connected user as pid.

On the previous example, you can modify the buffer as follows:

    pick 379ab2a Move all presence as pid.
    squash 42bab02 Update timeout module to use the new presence api.
    squash d1da4b4 No more indexes for uce_presence_mongodb.
    squash 94835c2 No more indexes for uce_presence_mnesia.
    reword 09b4224 Connected user as pid.

What's going to happen :

* 42bab02, d1da4b4 and 94835c2 will be merged with 379ab2a. Git will also offer to rewrite the commit message.
* You will be able to rewrite the commit message of 09b4224.
* Commit 0a481e9 being deleted from the buffer, it will also be deleted from the history.

    git help rebase

# Tip 32

I want to know all the commits since yesterday.

     git log --since yesterday

A little bonus today:

     git log HEAD^

Will list the commits from the penultimate commit.

     git log HEAD~4..

Will list the last four commits. Equivalent to :

     git log HEAD~4..HEAD

More informations:

     git help revisions

# Tip 33

I want to modify my last commit, because I put a bad commit message.

    git commit --amend

Modifies the last commit message. Can also add changes to your staging area.

    git add myfile.erl && git commit --amend

Will re-add myfile.erl modification to the previous commit.

This command rewrites the git history, you should NOT do this if you have already pushed.
# Tip 34

You have recurring conflicts during merges and you want to fix them once and for all.

The first thing to do is to configure the *rerere.enabled* variable.

    git config --global rerere.enabled 1

Next ? You let git do it. It will automatically record conflicts and their resolutions to do the same automatically.

At the next git pull --rebase or git merge, no need to reapply the same patch.

If you saved a bad resolution, you can use git rerere forget.

And why back off? It is the abbreviation of Reuse recorded resolution.

    git help rerer

    http://progit.org/2010/03/08/rerere.html

# Tip 35

I want to combine two git repositories into one:

    git replace SHA1 SHA2

The SHA1 commit will be replaced by SHA2 and all of its parents.

I've never used this command other than for testing, but it can be handy if you have a large history and don't need to keep it entirely.

This was done for the otp repository which is over 300MB: https://github.com/erlang/otp/wiki/Extending-the-history-of-Erlang-OTP.

You can easily test it with a few commands to link two repositories. Let's link the EventMachine and NodeJS repositories.

    $ git clone https://github.com/eventmachine/eventmachine.git
    $ git remote add nodejs https://github.com/joyent/node.git
    $ git fetch nodejs
    $ git replace d9a23e4779b3f555e63e4ff565ef0848a8bcabd4 61dfe5d2a9f613e3826997efa189ec8dd239aacf

Yes it is useless. But look at the git log and everything goes as if nothing happened.

    git help replace (but it's not going to help you much)

    http://progit.org/2010/03/17/replace.html

# Tip 36

Did you commit to any branch? Did you miss a git reset --hard? Have you tested git filter-branch on a repository with lots of super important patches?

    git reflog

Reflog logs all changes that are made to branches and the repository. You should see your commits, merges and other pulls there by default. A good spy who can get you out of trouble.

Here is a typical reflog output.

    d2bbd0e HEAD@{1}: commit: Run the bootstrap script when running bench.
    bd91916 HEAD@{2}: bd919164c72c38b88a85275ee5b9add7f7a8f382: updating HEAD
    2ce209e HEAD@{3}: pull origin master: Merge made by recursive.
    bd91916 HEAD@{4}: commit: Generate tsung scenario from a yml file.
    4cdc612 HEAD@{5}: checkout: moving from complex_metadata to develop
    44fb6fc HEAD@{6}: commit: Initial support of complex metadata in events.
    4cdc612 HEAD@{7}: checkout: moving from 4cdc61204e4ea5c6814c65c88e2ef19031c2cf6d to complex_metadata

For example, to check in a commit that is in no branch (*Not currently on any branch.*):

    git reflog (find the right commit, e.g. d2bbd0e)
    git checkout master
    git cherry-pick d2bbd0e

Or retrieve your repository after a git filter-branch:

    git reflog
     129b276 HEAD@{0}: filter-branch: rewrite
     bbd8de8 HEAD@{1}: rebase -i (pick): Optimize uce_paginate.
    git reset --hard bbd8de8

A few subcommands are available like *expire* and *delete*.

    git help reflog
