### Jouer avec nos révisions

Maintenant on a appris à créer des versions de notre code. Vous avez changé un fichier ? On tape `git commit -am'Added some CSS styles for header'` Voilà une nouvelle révision vient de se créer. 

#### Voir la liste des révisions `git log`

Nous pouvons maintenant taper `git log` cette commande, forte utile, liste toutes le modifications dans l'ordre. 

```console
commit fbb1521c3eace22485aaf9394a2d875e992daf42 (HEAD -> master)
Author: Ori Pekelman <ori@platform.sh>
Date:   Thu Oct 11 06:17:22 2018 +0100

    add .gitkeep so files will be added to the repository

commit 59c8961247a28b50e73a29f9c686e9d21b64c25f
Author: Ori Pekelman <ori@platform.sh>
Date:   Thu Oct 11 06:15:42 2018 +0100

    Adding a license file

commit b244fbb92edc16c7ac72dc4a19e3c67e0aff657e
Author: Ori Pekelman <ori@platform.sh>
Date:   Thu Oct 11 06:10:30 2018 +0100

    Add the list of commands we learnt today.

commit 5e8354a6e4215e11adc11cf3ca16c237f821dfad
Author: Ori Pekelman <ori@platform.sh>
Date:   Thu Oct 11 06:06:51 2018 +0100

    Added readme.md
```

Voilà on a une jolie liste de tout ce qui s'est passé. Et si on regarde de près il n'y a rien là qui doit nous surprendre ... **commit** et son **sha** puis l'auteur et finalement la date et notre message de commit. Une seule chose s'est ajoutée là, à la première ligne **(HEAD -> master)**. Nous expliquerons ça un peu plus bas. Pour le moment continuons...

Et si nous modifions `readme.md` pour rendre compte de ce qu'on vient d'apprendre? vous pouvez ouvrir votre éditeur de texte préféré et modifier `readme.md`, moi, je vais encore utiliser la ligne de commande pour ajouter la ligne.

```console
echo "\n5. \`git log\` voir toutes les révisions" >> readme.md
``` 
Et de nouveau on va ajouter un petit commit

```
git commit -am'added git log command'
```

Cool. Ca continuer à marcher. Maintenat si je tape à nouveau `git log` je verrai en haut de la liste mon nouveau commit:

```console
commit dc5139c9c77b0d2210301b3fdf68817311f57b2e (HEAD -> master)
Author: Ori Pekelman <ori@platform.sh>
Date:   Thu Nov 29 15:22:26 2018 +0100

    added git log command
```

#### Bouger vers une autre révision `git checkout`

Imaginons maintenant que nous voulons revenir dans le passé avant qu'on n'ait fait cette modification. 

Rien de plus simple: dans le log je vais regarder le **SHA** le hash du commit précédent et je peux maintenant taper:

```console
git checkout fbb1521
```

Sa réponse va être un peu verbeuse, ignorons pour le moment et regardons uniquement la première et dernière ligne:

```console
Note: checking out '817c439450d04ccabb7a09bebfd3d1d058f0bcf5'.
    # [bla bla bla bla Git tente d'être super utile]
HEAD is now at 817c439 add .gitkeep so files will be added to the repository
```

On est revenu dans le passé. Si on tape `cat readme.md` nous verrons notre fichier tel qu'il a été avant d'avoir ajouté note point 5.

Et nous pouvons de nouveau taper `git log` pour voir.

**Sapristi**! En effet nous sommes dans l'état précédent et notre dernier commit a complètement disparu. Est-il un bon moment de paniquer ? Non. Il ne faut jamais paniquer.

La commande:

```console
git log --branches
```

> :information_source:
> Git est une grosse bébête: pour chaque commande il y a parfois de dizaines d'options différentes. Nous allons, évidemment, uniquement voir les choses principales.

Donc `git log --branches` va nous montrer que l'on n'a rien perdu. Et en plus on va voir quelques informations intéressantes supplémentaires.

```console
commit dc5139c9c77b0d2210301b3fdf68817311f57b2e (master)
Author: Ori Pekelman <ori@platform.sh>
Date:   Thu Nov 29 15:22:26 2018 +0100

    added git log command

commit 817c439450d04ccabb7a09bebfd3d1d058f0bcf5 (HEAD)
Author: Ori Pekelman <ori@platform.sh>
Date:   Thu Oct 11 06:17:22 2018 +0100

    add .gitkeep so files will be added to the repository

commit ee169bcc1fc59fd3c24ae144da013d1f8f289498
Author: Ori Pekelman <ori@platform.sh>
Date:   Thu Oct 11 06:15:42 2018 +0100

    Adding a license file

commit 625ef35b031a9ea861e19a95dfba879e9a52a1ed
Author: Ori Pekelman <ori@platform.sh>
Date:   Thu Oct 11 06:10:30 2018 +0100

    Add the list of commands we learnt today.

commit 5e8354a6e4215e11adc11cf3ca16c237f821dfad
Author: Ori Pekelman <ori@platform.sh>
Date:   Thu Oct 11 06:06:51 2018 +0100

    Added readme.md
```
En effet `git log` par défaut nous montre le passé du point dans lequel on est. Rien n'a été perdu. Voilà le **log** qui est la même chose .. sauf une petite chose: là où en haut on avait **(HEAD -> master)**, maintenant **dc5139** est marqué comme **master** et **817c43** comme **HEAD**. De quoi s'agit-il ?

**HEAD** c'est un pointeur vers là où on est actuellement. On était sur le commit **dc5139c** et maintenant notre zone de travail est, dans le passé sur **817c43**. 

Si maintenant on fait `git checkout master` le pointeur **HEAD** va à nouveau se positionner sur notre tout dernier commit celui qui a le message "added git log command". Nous pouvons le vérifier avec `git log` ou `git log --branches` (qui là, donc vont faire précisément la même chose).

Mais c'est bizarre, on a appris à faire `git checkout {sha}` et maintenant nous au lieu de mettre plein de caractères bizarres on écrit en toutes lettres **master**.

Donc c'est quoi **master** ? **master** est une branche. Nous vous l'avons déjà raconté à l'introduction, avec Git nous pouvons travailler non seulement sur des révisions comme une seule flèche temporelle ... mais sur des multiples versions différentes, en même temps. **master** ou _maître_ en Français est comme son nom l'indique: la version maîtresse, le haut de l'arbre. Un peu plus tard nous allons vous montrer comment créer d'autres branches, comment utiliser `git checkout` pour sauter de l'une à l'autre, pour le moment restons avec un seul tronc.

> :information_source:
> Dans d'autres système de gestion de version, comme les vénérables CVS ou SVN cette branche maîtresse s'appelait en effet "Trunk" ou en Français "tronc" ce qui donne bien l'image de cette branche principale de laquelle toutes les autres sortent. Pour Git c'est une simplification, il est si puissant et malléable que ce concept est réducteur ... mais voilà, on va pas trop se compliquer la vie toute-de-suite. Imaginez donc **master** comme le tronc principal. 

Comme c'est le case pour **HEAD** une branche est simplement un pointeur vers un **commit**. Et souvent le **HEAD** pointe vers le haut de la branche sur laquelle on est. Comme nous sommes sur la branche **master**, **HEAD** pointe vers le "haut" de celle-ci. Notre dernier commit.

Nous aimons regarder sous les capot n'est-ce pas? regardons quelques autres structures de données à l'intérieur de notre cher `.git` pour être sûr de bien comprendre.

Assurez-vous d'avoir fait `git checkout master` et nous pouvons essayer les commandes suivantes

```console
cat .git/HEAD
```
Qui va nous sortir: 

```console
ref: refs/heads/master
```
Donc ceci est une référence, qui pointe vers `refs/heads/master` -- ce truc là, c'est aussi un fichier sous `.git`. Nous pouvons suivre la trace et taper:

```console
cat .git/refs/heads/master
```

Et il va nous répondre par le **SHA**, le **commit-id** de notre tout dernier commit:

```console
dc5139c9c77b0d2210301b3fdf68817311f57b2e
```

Un peu plus tôt quand nous avons fait `git checkout 817c439`, git a donné un gros message que nous avions choisi d'ignorer, lisons le maintenant:

```console
Note: checking out '817c439'.

You are in 'detached HEAD' state. You can look around, make experimental
changes and commit them, and you can discard any commits you make in this
state without impacting any branches by performing another checkout.

If you want to create a new branch to retain commits you create, you may
do so (now or later) by using -b with the checkout command again. Example:

  git checkout -b <new-branch-name>

HEAD is now at 817c439 add .gitkeep so files will be added to the repository
```

C'est qu'il nous dit là c'est en gros: hé vous avez choisi de faire un `checkout` non pas sur le haut de la branche, mais sur un **commit** spécifique. **HEAD**, la tête, le pointeur de l'état actuel est maintenant "détachée" de sa branche (retenez en Anglais "Detached head").

#### Récapitulatif `git log` et `git checkout`

* `git log` nous permet de voir la liste des **commit**s dans le passé. 
* `git checkout` nous permet de passer le pointeur du **commit* actuel de la zone de travail à un **commit** spécifique il change le pointer **HEAD** et il remet notre zone de travail à l'état qu'il avait lors de ce commit.
* **master** est une branche de notre code, même la branche principale
* nous pouvons faire `git checkout {le-nom-d-une-branche}` car la branche est simplement un pointeur vers un **commit** donc `git checkout master` nous ramène à en haut de notre arbre, à notre dernier **commit**
* **detached head** c'est la situation dans laquelle notre pointer **HEAD** ne pointe pas vers le dernier commit d'une branche.
