### Configurer Git avec une clé SSH

> :info: La plupart de serveurs Git s'authentifient à l'aide de clés publiques SSH (pour en apprendre plus https://openclassrooms.com/fr/courses/43538-reprenez-le-controle-a-laide-de-linux/41773-la-connexion-securisee-a-distance-avec-ssh ). Il vous faudra créer une nouvelle clé si vous n'en avez pas une. Ce processus est similaire dans tous les systèmes d'exploitation. 

> SSH est un protocole qui nous permet de nous connecter sur des machines distantes. Pour l’utiliser il faut se créer une “identité” qui est composée de deux fichiers l’un public, l’autre privé (le privé, il faut vraiment bien le protéger, c’est un peu comme votre mot de passe).

> Si SSH n’est pas requis pour l'utilisation de Git, vous allez être vite limité dans votre usage sans celui-ci, on a déjà, potentiellement un tout petit peu souffert pour installer Git.. Souffrons dans l’immédiat un peu plus.. Comme ça après c’est un long fleuve tranquille.

#### Créer sa paire de clés SSH


Tout d'abord, vérifions que vous n'en avons pas déjà une clé. Par défaut, les clés SSH d'un utilisateur sont stockées dans le répertoire ~/.ssh de cet utilisateur. Vous pouvez facilement vérifier si vous avez déjà une clé en allant dans ce répertoire et en listant le contenu :

```console
ls -a ~/.ssh
-r--------  1 oripekelman  staff   3243 Jun 24 10:57 id_rsa
-rwxrwxrwx  1 oripekelman  staff    741 Jun 24 10:57 id_rsa.pub
-rw-r--r--  1 oripekelman  staff  2410  Jun 24 10:57 config
-rw-r--r--  1 oripekelman  staff  11120 Oct 22 15:07 known_hosts
```


Vous cherchez une paire de fichiers nommés id_dsa ou id_rsa et un fichier correspondant avec une extension.pub. Le fichier.pub est votre clé publique et l'autre fichier est votre clé privée (vous pouvez noter dans notre liste du répertoire à gauche une différence dans les droits des fichiers. id_rsa, ma clé privée est en lecture seule .. et uniquement pour moi. Pendant que la clé publique id_rsa.pub .. elle a les droits totalement ouverts. Elle est publique.) .

Si vous n'avez pas ces fichiers (ou vous n'avez même pas de répertoire.ssh), vous pouvez les créer en exécutant un programme appelé ssh-keygen, qui est fourni avec le paquet SSH sur les systèmes Linux/Mac et livré avec Git pour Windows :

```console
ssh-keygen -o
```

Il confirme d'abord où vous voulez sauvegarder la clé (`.ssh/id_rsa`): gardez l'option par défaut. Puis il demande deux fois une phrase de passe, que vous pouvez laisser vide si vous ne voulez pas entrer un mot de passe lorsque vous utilisez la clé. 

Vous pouvez également utiliser l'outil `ssh-agent` pour éviter d'avoir à entrer le mot de passe à chaque fois.

#### Configurer le serveur Git avec sa clé SSH

##### Github

Maintenant qu'on est sûr qu'on a notre clé... il suffit de configurer le serveur Git avec celle-ci. Par exemple avec github.com on peut sur https://github.com/settings/keys clicquer sur "New SSH Key" puis coller le contenu de son fichier id_rsa.pub


> :warning: Jamais oh jamais. La clé privée, `id_rsa` ne doit quitter votre ordinateur. Ca ne se sauvegarde même pas une clé privée.  C'est bien, uniquement la clé publique qui doit être envoyée.

##### Platform.sh
Avec platform.sh c'est encore plus simple une fois que vous avez l'outil à la ligne de commande `platform` installée tapez simplement:

```console
platform ssh-key:add
```
Et ils s'occupera du reste.
