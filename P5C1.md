Chapitre III: Débuter avec l’utilisation de Git. Installation et première commande.

Comme nous l’avons indiqué il y a bien de manières à utiliser Git (par le web, avec un GUI, un IDE) mais nous allons nous concentrer sur son usage à la ligne de commande, avec la version “officielle”, vous pouvez la trouver ici: https://git-scm.com/download/ 

> CADRE Ligne de commande
> Si vous n'êtes pas à l'aise avec un terminal, je vous invite à faire un passage rapide sur: https://openclassrooms.com/fr/courses/43538-reprenez-le-controle-a-laide-de-linux/38076-entrer-une-commande vous aller voir on y prend goût rapidement. 

> CADRE bonnes pratiques
> Pour débuter, ceci suffira. Mais sachez que chaque système d’exploitation a sa manière  préférée d’installer des logiciels de sorte qu’il soit simple de les mettre à jour. Ainsi sur un Linux de type Ubuntu ou Debian nous préférons taper à la ligne de commande `sudo apt-get install git-all` sur un dérivé de Redhat `sudo dnf install git-all`. Sur Mac, deux options simples la première est d’installer Xcode, la deuxième est d’utliser le système de gestion de paquet à la ligne de commande HomeBrew et taper `brew install git`. Pour ce qui est de windows, nous vous conseillons soit de suivre la même méthode que pour Mac, en installant Chocolatey puis `choco install git` soit (encore mieux) en install le Windows Subsystem for Linux  vous pourrez ensuite retomber sur vos pattes et suivre les instructions pour Ubuntu (donc `sudo apt-get install git-all`).  En effet si Git existe pour tous les systèmes d’exploitation courants (Windows, Mac OS X, Linux) et il fonctionne de la même manière  partout,  sur les anciens systèmes Windows son utilisation était très difficile (comme la plupart des outils à la ligne de commande qui visent des système similaires à Linux).


## Tester la bonne installation:

Ouvrez un terminal et tapez à la ligne de commande `git` + la touche entrée. Vous devriez voir un long texte d’aide qui apparaît avec plein de mots très anxiogènes. Respirez profondément. Vous pouvez ignorer tout ceci pour le moment.

```console
usage: git [--version] [--help] [-C <path>] [-c <name>=<value>]
           [--exec-path[=<path>]] [--html-path] [--man-path] [--info-path]
           [-p | --paginate | -P | --no-pager] [--no-replace-objects] [--bare]
           [--git-dir=<path>] [--work-tree=<path>] [--namespace=<name>]
           <command> [<args>]

These are common Git commands used in various situations:

start a working area (see also: git help tutorial)
   clone      Clone a repository into a new directory
   init       Create an empty Git repository or reinitialize an existing one

work on the current change (see also: git help everyday)
   add        Add file contents to the index
   mv         Move or rename a file, a directory, or a symlink
   reset      Reset current HEAD to the specified state
   rm         Remove files from the working tree and from the index

examine the history and state (see also: git help revisions)
   bisect     Use binary search to find the commit that introduced a bug
   grep       Print lines matching a pattern
   log        Show commit logs
   show       Show various types of objects
   status     Show the working tree status

grow, mark and tweak your common history
   branch     List, create, or delete branches
   checkout   Switch branches or restore working tree files
   commit     Record changes to the repository
   diff       Show changes between commits, commit and working tree, etc
   merge      Join two or more development histories together
   rebase     Reapply commits on top of another base tip
   tag        Create, list, delete or verify a tag object signed with GPG

collaborate (see also: git help workflows)
   fetch      Download objects and refs from another repository
   pull       Fetch from and integrate with another repository or a local branch
   push       Update remote refs along with associated objects

'git help -a' and 'git help -g' list available subcommands and some
concept guides. See 'git help <command>' or 'git help <concept>'
to read about a specific subcommand or concept.
```

Sur OS X si l’installation ne s’est pas bien passée il risque de vous proposer d’installer XCode. Faîtes.  

> Créer sa paire de clés SSH
> SSH est un protocol qui nous permet de nous connecter sur des machines distantes. Pour l’utiliser il faut se créer une “identité” qui est composée de deux fichiers l’un public, l’autre privé (le privé, il faut vraiment bien le protéger, c’est un peu comme votre mot de passe).

> Si SSH n’est pas requis pour l'utilisation de Git, vous allez être vite limité dans votre usage sans celui-ci, on a déjà, potentiellement un tout petit peu souffert pour installer Git.. Souffrons dans l’immédiat un peu plus.. Comme ça après c’est un long fleuve tranquil.
