### On sait sauvegarder ... mais comment modifier ?  supprimer ?  annuler? 

Rappelons nous deux choses importantes: les **commit**, pointe vers un **tree-id** donc une arborescence et un contenu des fichiers dans un état spécifique, puis il point aussi vers des **parents**. Donc des **commits** précédents (qui eux, naturellement pointent à leur tour à des **tree-id**s). Supprimer est donc chose simple. Si dans le **tree** de notre **commit** actuel il y a un fichier qu'il n'y a pas dans le **tree** du **commit** parent .. alors ce qu'il a été supprimé.

#### Supprimer un fichier avec Git

Nous pouvons tester ça. Disons que nous ne souhaitons plus avoir le fichier LICENSE. 

```console
rm LICENSE
```

Maintenant `git status`  va nous dire:

```console
On branch master
Changes not staged for commit:
  (use "git add/rm <file>..." to update what will be committed)
  (use "git checkout -- <file>..." to discard changes in working directory)

	deleted:    LICENSE

no changes added to commit (use "git add" and/or "git commit -a")
````
Cela veut dire que le fichier LICENSE existe dans l'**index** mais n'existe pas dans la zone de travail. Pour le supprimer on va devoir ajouter à l'index la suppression. Donc `git add LICENSE`. Puis nous allons appliquer ce changement avec un `git commit -m"Remove license file"`.

```console
[master 6732b04] Remove license file
 1 file changed, 8 deletions(-)
 delete mode 100644 LICENSE
```
Voilà le fichier a disparu.

> :information_source: Comme nous avons compris... tout reste dans l'historique, notre commit actuel pointe vers un objet **tree** dont l'arborescence ne contient pas ce fichier. Mais le **commit** précédent pointe vers un **tree** qui le contient.

Mais tout ceci est fastidieux et git nous donne une commande unique pour enlever le fichier aussi bien de la zone de travail comme de l'index. 

```console
git rm LICENSE
git commit -m"Remove license file"
```

Est parfaitement équivalent à ce que nous venons de faire... si le fichier n'a pas été modifié (autrement Git va se plaindre et refuser de le faire).

#### Changer les noms de fichiers et de répertoires

Précisément de la même manière nous pouvons procéder à des renommages. Mais là, on a tout intérêt à utiliser plutôt toujours la commande intégrée.

Pour changer le nom de notre répertoire `files` en `media` rien de plus simple:

```console
git mv files media
```

Voila un petit `git status`nous dira:

```console
On branch master
Changes to be committed:
  (use "git reset HEAD <file>..." to unstage)

	renamed:    files/.gitkeep -> media/.gitkeep
```
Comme toujours pour appliquer les changements, un **commit**:

```console
git commit -m'Rename files to media'
```

Qui nous dira:
```console
[master cd352ab] Rename files to media
 1 file changed, 0 insertions(+), 0 deletions(-)
 rename {files => media}/.gitkeep (100%)
```

> :warning: Petit subtilité: Git ignore d'habitude les répertoires vides (souvenez-vous, c'est pour cela que nous avons crée le petit fichier caché `.gitkeep`). Mais ici, si le répertoire media existait déjà (qu'il existe dans notre **index** ou non) le résultat de la commande sera différent et notre `files` se retrouvera à l'intérieur de `media` avec une arborescence comme ceci: `media/files/.gitkeep`. 

Nous aurions pu évidemment utiliser les commandes de notre système d'exploitation pour faire de renommage mais notre historique alors eut été moins bien belle.

```console
➜  my_first_git_project git:(master) mv files media
➜  my_first_git_project git:(master) ✗ git status
On branch master
Changes not staged for commit:
  (use "git add/rm <file>..." to update what will be committed)
  (use "git checkout -- <file>..." to discard changes in working directory)

	deleted:    files/.gitkeep

Untracked files:
  (use "git add <file>..." to include in what will be committed)

	media/

no changes added to commit (use "git add" and/or "git commit -a")
```

En effet Git ne peut pas détecter que files a changé de nom. Il voit sa disparition ainsi que l'apparition d'un répertoire non-vide qu'il ne gère pas. 

> :information_source: Nous y reviendrons mais notre ambition en utilisant Git est de garder une historique "propre". Cela facilite énormément la collaboration. Donc pour ce qui est de renommer des fichiers et de répertoire dans un dépôt Git **utilisez toujours `git mv` plutôt que `mv`.**


#### Récapitulatif `git rm` `git mv`

* `git rm` nous permet de supprimer de fichiers et de répertoires
* `git mv` nous permet de renommer de fichiers et de répertoires
